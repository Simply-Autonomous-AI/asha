Quality controls

What stops a defect from reaching a commit. Human review is optional (PRINCIPLES §21), so these controls have to catch defects on their own.

verified 2026-09-27; the linter and formatter 2026-10-12, in the gate 2026-10-14gate: npm run checklinter: ESLint, typescript-eslint and SonarJS, and Prettier, the gate's first two linkssources: tsconfig.json, eslint.config.mjs, .prettierrc.json, package.json, AGENTS.md, src/daemon/log.ts

In short

  • npm run check is the gate: lint, format check, typecheck, unit, integration, demo selection, agents, eval, routing, stopping at the first failure. Nothing is done until it is green.
  • The typecheck is strict, TypeScript is pinned at 6.0.3, and Node APIs stop at 22.13; a test proves each strict setting.
  • ESLint (type-checked typescript-eslint and SonarJS, every rule on but four design exemptions) and Prettier run as npm run lint and npm run format:check, the gate's first two links since 2026-10-14 (docs/plans/lint-format.md).
  • A guard counts only once it has been seen to fail.
  • Definitions are closed schemas, models are pinned by sha, every failure lands in one JSON log, and every remote call is bounded.
  • Every change gets one adversarial review and must pass the checklists.

Static analysis

TypeScript typecheck built

npm run typecheck runs tsc --noEmit -p tsconfig.json with TypeScript 6.0.3 over src/ (less src/portal/), images/*/src/, evals/, tools/ (the .mts files, such as tools/docs/render.mts), tests/ and the Vitest configs; then tsc --noEmit -p tsconfig.portal.json over the portal's page, src/portal/, and the shared modules it loads, with ES2024 and the DOM library and no Node types ("types": []), so a Node global such as Buffer in any module the page loads fails the check (docs/plans/portal.md R15); then tsc --noEmit -p tsconfig.dom-tests.json over the unit tests of the page's browser modules (tests/**/*.dom.test.ts) and their fakes (fake-dom.ts, fake-canvas.ts), with the DOM library and Node's types both, which tsconfig.json leaves out so no Node module may name a DOM type. npm run build compiles the first two, the page into dist/portal-build/. The Node API floor: @types/node is ~22.13.0, the floor of engines, so callable Node APIs stop at 22.13; the docs guard asserts both. It is the lowest the toolchain accepts: engines is the intersection of the ranges Vitest 5.0.2 declares, ^22.12.0 || ^24.0.0 || >=26.0.0, and ESLint 10.12.0, ^20.19.0 || ^22.13.0 || >=24 — ^22.13.0 || ^24.0.0 || >=26.0.0 (docs/plans/lint-format.md R10 (b), since 2026-10-14; before it, Vitest's range alone and a 22.12 floor) — and Vite 8.3.1 requires @types/node ^20.19.0 || >=22.12.0 (each from its installed package.json, read 2026-10-14).

Warning

A newer @types/node declares APIs this floor lacks, such as Float16Array (Node 24) and registerHooks from node:module (Node 22.15). Those would typecheck and then throw at run time. One already does: @types/node 22.13.17 declares findPackageJSON (its own @since v23.2.0, v22.14.0), which is undefined on Node 22.13.1 — the only declaration in the package past 22.13.0 (its @since tags, read 2026-10-14). Nothing here calls it.

Why TypeScript 6.0.3, not 7.x

The owner, 2026-09-27 (debt D7)

TypeScript stays on 6.0.3, because TypeScript 7.0 has no stable compiler API.

  • 7.0 "does not ship with an API"; the team expects "TypeScript 7.1 to ship with a new (and different) API" (Announcing TypeScript 7.0, 2026-07-08, read 2026-09-27). The typescript@7.0.2 main entry exports only the version; its API is under typescript/unstable/* (its exports map, read 2026-09-27).
  • Tools on the stable API do not run on 7.0: typescript-eslint 8.70.1 peers >=4.8.4 <6.1.0, TypeDoc 0.28.20 5.0.x … 6.0.x (npm registry, read 2026-09-27). Since 2026-10-12 typescript-eslint 8.71.1 runs the linter (its peer range, read that day, still >=4.8.4 <6.1.0); TypeDoc is not installed.

Linter built

npm run lint runs ESLint 10.12.0 as eslint --max-warnings 0 ., with the configuration in eslint.config.mjs; npm run lint:fix applies the rules' own fixes. The first link of the gate since 2026-10-14, about 36 s on this Mac: when it was added on 2026-10-12 the tree held 6,316 findings in 315 of the 396 files it reads, and the docs/plans/lint-format.md plan fixed every one in the code, the configuration unchanged (its R6). Check a file you write or rewrite before the gate does: npx eslint <file>.

  • The rules. Three presets, every rule on at error with its own options: ESLint's recommended (@eslint/js 10.0.1); typescript-eslint 8.71.1's strictTypeChecked, which reads types from the three programs npm run typecheck checks (tsconfig.json, tsconfig.portal.json and tsconfig.dom-tests.json) and so finds a promise nobody awaits, a condition that is always true, a value printed as [object Object]; and SonarJS's recommended (eslint-plugin-sonarjs 4.2.2), the bug and code-smell rules of SonarQube's JavaScript analyzer, among them cognitive complexity, duplicated branches and super-linear regular expressions. Plain JavaScript, which neither program holds, gets the rules that need no types.
  • What it reads. Every tracked .ts, .mts, .cts, .js, .mjs and .cjs file but the dated probes under evals/probes/, which stay as they ran, and the copies of them under tests/fixtures/probes/ that shipped tests read (tests/fixtures/README.md; Prettier skips tests/fixtures/agent-results/ too); nothing in what .gitignore or .git/info/exclude keeps out (dependencies, build output, .claude/, .qa/).
  • No exemption in the code. noInlineConfig makes an eslint-disable comment inert and reports it, and --max-warnings 0 fails on that report; an exemption lives only in eslint.config.mjs, with its reason. There are four, each where the rule's demand contradicts the design:

The gate

npm run check is the whole gate; the repo has no deploy path (AGENTS.md §2). Its links are joined by &&.

  • The secret scan (npm run scan:secrets, after the typecheck since 2026-10-16, docs/plans/oss-release.md R5): gitleaks 8.30.1 or later below 9, with its default rules only, over a temporary copy of exactly the tracked files; a finding is printed by file, line and rule, never its value, and fails the gate (tools/oss/secrets.mts). Proven: the secret fakes of files-secrets.test.ts before their fix gave two findings, and the scan made to return none failed four of secret-scan.test.ts's cases.

  • The shipped-file guard (shipped-files.test.ts, in npm test, R11): no file the public export ships holds a home folder's path, a .claude/ path, a machine's temporary folder, a path into a home folder's Documents, Desktop or Downloads, or a private address but the allowed ones, each with its reason. Proven by a planted home path and address in docs/index.md, and by the probe copy it caught.

  • The marker scan (npm run oss:scan-markers -- <dir>, R9; run by npm run oss:check, not by the gate): the private values the owner keeps in a file outside every repository, none of them printed; marker-scan.test.ts plants each kind in each place.

  • The demo selection (npm run demos:select, Testing): before the agent suite, it records which pattern demos the change since the last green gate touches, three repeats for those and one for the rest, and fails closed — a path it cannot place, or a base it cannot trust, selects every demo; a git command that fails stops the gate.

  • Bounds are guards: 20 minutes per agent or eval test (testTimeout: 1_200_000), because a cold run downloads a 5 GB model. Hitting one is a failure, not a flake (PRINCIPLES §14.5).

  • Agent files run one at a time (fileParallelism: false): each starts its own daemon, and two would load the model twice.

  • Never bypassed: no .skip, no retries, no subset in place of the gate (PRINCIPLES §8).

Determinism

  • Exact assertions need greedy decoding: a recipe whose output the gate asserts exactly sets chat.temperature: 0 (AGENTS.md §3), merged over the catalogue's sampling defaults. Both recipes do: recipes/hello-world.json, recipes/memory.json. Measured, not assumed (History).
  • Never loosen an assertion. If an upgrade changes the output, re-verify and update the expectation (PRINCIPLES §8).
  • A timed-out test cannot move the next test's fake clock (tests/helpers/fake-clock-guard.ts, the unit and integration suites' second setup file): vitest moves on from a test that times out while its body runs on, so each test runs with its own signal and vi's clock moves refuse once it has aborted. Proven (fake-clock-guard.test.ts): the abort check, the per-test binding, the setup file and one listed move, each removed, failed it; and with a test forced to time out, the files that showed the knock-on (restart.test.ts, persistence-stop.test.ts, as they stood before e23af9b) failed only that test (2026-10-11).
  • Every turn ends in a tool call: channel turns send tool_choice: "required", so no stray text is lost.
  • Prompt caching can change greedy output. llama.cpp's server README warns that cache_prompt "can cause nondeterministic results", because logits are not guaranteed bit-identical between batch sizes (read 2026-09-28 at 7fe450e19); the routing eval already showed a temperature-0 pass reason differ between a cold and a cached attempt at 6da73b2. Closed-schema definitions

Recipes (recipes/*.json), images and catalogue entries (catalogue/*.json) are validated once, where they enter, by Definitions in src/daemon/definitions/index.ts. closedObject rejects any unknown key, so a typo fails loudly; an unknown name throws UnknownRecipe or UnknownImage. Tests: tests/unit/definitions.test.ts.

Pinned, verified models

  • Each catalogue entry pins a Hugging Face repo at a commit revision, plus the size and sha256 of every file.
  • The model store (src/daemon/model-store/index.ts) downloads to staging, verifies every sha256, then renames atomically to models/sha256-<tree digest>/. A mismatch is fatal and never retried. Only GGUF or safetensors weights are allowed.
  • Each entry records its licence id, source URL at that revision, and date read (license.verified); see Models. Agent images carry an asha.source label, a digest of their build context, and are tagged by it (asha-image-<name>:<digest hex>); a changed context is a new tag, so a stale image is never reused and no tag is replaced.

Error surfacing

  • One facade: JsonLinesLogger in src/daemon/log.ts writes each record synchronously as one JSON line in <ASHA_HOME>/logs/daemon.jsonl, echoed to stderr, so it is on disk before any crash that follows.
  • Errors keep their detail: name, message, stack and cause chain; ts, level and event are set last so no field can hide an error. Events: Architecture: logs.
  • Expected external failures are data: the model gateway returns {ok:false, reason, detail}.
  • Refusals are findable and bounded: every 401 and 403 is a warn record http.refused with its reason and count, one per reason and API per second at most (the guard): jq -c 'select(.event=="http.refused")'.
  • Isolation fails closed and loudly: a container that cannot be confined to the daemon's port is never started; the launch fails with ContainerIsolationFailed (logged as launch.failed or conversation.agent_unavailable, reason container_runtime), naming the rule, network or check, with the command's output. A failure to remove a home's rules or network is daemon.reclaim_failed and fails the start or the stop (reaching the host).
  • Nothing guesses an environment: a missing ASHA_URL, ASHA_AGENT_TOKEN or docker socket fails loudly. Tests: tests/unit/log.test.ts.

the 3am query (PRINCIPLES §11)

jq -c 'select(.level=="error")' ~/.simplyautonomous/harness/logs/daemon.jsonl

Every remote call is bounded, for example: CLI health check 3 s, daemon start 20 s, stop 90 s, an agent draining its started work at stop 65 s inside a 70 s stop grace, model chat 60 s, llama-server ready 120 s, model download stall 60 s, brew install 15 min, colima start 10 min, each colima ssh that installs or removes the container rules 30 s.

A bound survives a garbage collection: a timeout combined with another signal is made only by withTimeout (src/shared/abort.ts). On Node 22, AbortSignal.any([AbortSignal.timeout(ms), …]) holds its sources weakly, and a collection left such a call unbounded (2026-10-11); withTimeout holds the timeout signal by a timer until it fires. A guard in tests/unit/abort.test.ts fails on any AbortSignal.any(…) in src/ or an image's source that holds AbortSignal.timeout( or a name assigned from it.

Adversarial review and checklists

Every change gets an adversarial review by a fresh agent before it is reported done — a change that touches code through the review loops in sdlc/, anything else in one round — and every plan two (plan and completion); in a one-round review, findings are fixed, rebutted with evidence, or declined as not material, and the completing commit carries a Review: trailer. Correctness, security, data-loss and principle findings are never declined (PRINCIPLES.md §18–§19). Docs are reviewed against the contract. The workflow and prompts: Workflows: adversarial review. The checklists define done, and the item that should have caught an escaped defect is amended (§21).
