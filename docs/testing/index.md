## The gate and the pyramid {#gate}

`npm run check` ([package.json](../../package.json)) runs each step in order and stops at the first failure. The first two, since 2026-10-14 (`docs/plans/lint-format.md` R10), are the [linter and the format check](../quality/index.md#lint), about 36 s and 5 s on this Mac; then the typecheck. The agent suite and the eval run `npm run build` first, because they drive the built `./asha`. Before the agent suite, a build and the [demo selection](#selection) (`npm run demos:select`, since 2026-09-29). The last step, `npm run eval:routing:gate` (since 2026-09-29, `docs/plans/agent-calls.md` R18), runs the [routing eval](#routing) on the `dist/` the eval built, with no build of its own: about 156 s in the gate at `1315ddb` (12 min 9 s in all, 12:57:30–13:09:39 UTC), 153 s in its proof of failure. Proven to fail: with `consult` taken out of an agent's tools it exits 1 naming the ask-for-yourself cases (`docs/plans/agent-calls.md` A10).

**Run it with the Mac awake:** on power, its lid open, under `caffeinate -dims npm run check`, and read the power log for the run's window afterwards (`pmset -g log | grep -E 'Sleep|Wake'`). A sleep pauses every timer, so a test or a CLI waiting on the daemon fails after the wake for no fault of the code: on 2026-10-16 a closed lid failed one integration test (1,019 s, the length of the sleep) and, in the next gate, two agent suites (D69, withdrawn). The same holds for `npm run demos:record` and `npm run demos:reel` ([below](#videos)).

## Unit tests <span class="badge built">built</span> {#unit}

**Config** [`vitest.config.mts`](../../vitest.config.mts) (includes `tests/unit/**/*.test.ts`) · **Command** `npm test` · **Output** vitest's console report only · **Coverage** `npm run test:coverage`: line and branch coverage of `src/` and `images/*/src/` by `@vitest/coverage-v8` (pinned to vitest's version), into `coverage/`, which git ignores

"Every collaborator is injected. No network, no docker, no model." Inputs are fixtures built per test. The doubles:

| File | What it fakes |
|---|---|
| [`tests/helpers/fakes.ts`](../../tests/helpers/fakes.ts) | Doubles that record every call, for exact call assertions |
| [`tests/helpers/daemon-fakes.ts`](../../tests/helpers/daemon-fakes.ts) | The daemon's adapter contracts and a fixture repo root, shared with integration |
| [`tests/helpers/llama-stream.ts`](../../tests/helpers/llama-stream.ts) | llama-server's streamed chat completion, synthetic in the shape the pinned server writes (confirmed by model-streaming's paired captures, which the gateway's tests also replay) |
| [`tests/unit/memory/fakes.ts`](../../tests/unit/memory/fakes.ts) | A deterministic word-hash embedder and a scripted model |

**A test that writes an executable pays macOS's first run of it.** macOS assesses each new executable file the first time it runs: about 1 s a file on 2026-10-16 (3 ms for `/bin/sh -c true`, 66 ms for a script run before), which timed out the fake-iptables tests, each writing three new fakes for each VM. A fake command is written once per test process and run once in a `beforeAll` with its own bound ([`fake-iptables.ts`](../../tests/helpers/fake-iptables.ts), `warmFakeCommands`).

**A test that times out runs on.** Vitest fails it and moves to the next test, but its body keeps running, on the fake clock the next test now uses. On 2026-10-11, under a load average of 11, a timed-out restart test moved the next test's clock past the time it asked for ("Negative ticks are not supported"). So the unit and integration suites load a second setup file, the fake-clock guard ([`tests/helpers/fake-clock-guard.ts`](../../tests/helpers/fake-clock-guard.ts)): each test runs with its own `signal`, which vitest aborts when it times out, and every call of `vi`'s that moves the clock or fires its timers refuses once the calling test's signal has aborted — the timed-out body stops at its next move, and the next test's clock stays its own ([`fake-clock-guard.test.ts`](../../tests/unit/fake-clock-guard.test.ts)). What it does not stop: a timer the timed-out body's code sets before that move lands on the next test's clock. Reading a red run, take a file's first failure first: one after a timeout may be its knock-on.

### Each run's temporary folder {#run-temp}

Tests make their homes, fixture roots and work folders with `mkdtemp(join(tmpdir(), …))` and seldom remove them: by 2026-10-15, 844,000 `asha-*` folders, 214 GB, filled this Mac's temporary folder. So every vitest config's first `globalSetup`, [`tests/helpers/run-temp.global.ts`](../../tests/helpers/run-temp.global.ts) ([`run-temp.ts`](../../tests/helpers/run-temp.ts)), makes a folder for the run, `asha-run-<pid>-XXXXXX` in the temporary folder, points `TMPDIR` at it — `os.tmpdir()` reads it on every call, in vitest's process and in every worker it starts — and removes it, everything in it, at the run's teardown. A run killed before its teardown leaves its folder; the next run's setup removes every run folder whose vitest process has ended. Measured 2026-10-15: no `asha-*` entry left in the temporary folder after a full unit run and a full integration run, from 0 before. A Unix socket's address is limited to 104 bytes on macOS, and paths under a run folder pass it, so a test binds a socket through [`listenAt`](../../tests/helpers/unix-socket.ts) (bound under `/tmp`, renamed into place). The daemons a run starts (`docs/plans/idle-shutdown.md`) end with it too (`TEST_DAEMON_ENV`). Checked by [`run-temp.test.ts`](../../tests/unit/run-temp.test.ts) and [`test-daemons.test.ts`](../../tests/unit/test-daemons.test.ts).

### One agent suite or eval at a time {#suite-lock}

The agent suite and the eval time real launches and model calls against the owner's bounds, which a busy CPU breaks (the `01f037a` failure, [below](#results)). So their configs take `/tmp/asha-agent-suite.lock` in `globalSetup` ([`tests/helpers/take-agent-suite-lock.global.ts`](../../tests/helpers/take-agent-suite-lock.global.ts)), holding vitest's own pid, and release it at teardown: a second agent suite or eval anywhere on the machine fails to start with `AgentSuiteRunning`, naming the holder pid, and a lock left by a dead pid (a killed run) is reclaimed and logged `lock.stale_cleared`. The unit and integration configs (and the live and screenshots configs, which share their global setup) first register their run as `/tmp/asha-light-runs/<pid>` (replacing a killed run's registration left under the same pid), then refuse to start while a live process holds the lock ([`tests/helpers/refuse-agent-suite.global.ts`](../../tests/helpers/refuse-agent-suite.global.ts)), with the same message, removing the registration when refused and at their teardown; and an agent suite or eval, once it holds the lock, waits while any registered run is alive — polling every 1,000 ms, saying once on stderr which pids it waits for, removing a dead run's registration (logged `suite.stale_registration_cleared`), and failing after 300,000 ms naming the live pids (`agentSuiteSetup`, `registerLightRun`, `waitForLightRuns`; `docs/plans/debt-paydown.md` R20, since 2026-10-03). Registering before the check closes the window where a unit run checked, found no lock, and an agent suite took it and started beside it. `npm run check` is never refused by itself: it runs unit and integration before the agent suite takes the lock, and the eval takes it only after the agent suite released it. The path is fixed rather than `$TMPDIR`, which differs between processes of one user. Logic in [`tests/helpers/suite-lock.ts`](../../tests/helpers/suite-lock.ts) (`takeAgentSuiteLock` reuses `acquirePidLock`, [`src/daemon/process/pid-lock.ts`](../../src/daemon/process/pid-lock.ts)); tests in [`tests/unit/suite-lock.test.ts`](../../tests/unit/suite-lock.test.ts) and [`tests/integration/agent-suite-lock.test.ts`](../../tests/integration/agent-suite-lock.test.ts) (a real `vitest --config vitest.config.mts` exits non-zero naming the holder while it is held; the agent-suite setup waits on a live child's registration and proceeds within 2 s of its exit). A stale lock is cleared only under a clear-sentinel (debt-paydown R19, [`tests/unit/pid-lock-race.test.ts`](../../tests/unit/pid-lock-race.test.ts)). Not covered (D29, narrowed): a clearer that dies inside the sentinel, followed by two others removing it at once; and other load beside an agent suite — `npm run build`, `npm run docs`, a probe — which registers nothing.

### Recording the demo videos {#videos}

Each pattern demo's video (`docs/plans/demo-videos.md`) is its agent-suite file run once with a recorder beside it ([`recorder.ts`](../../tests/agents/patterns/recorder.ts)), then encoded once; the combined video plays every demo's video in turn and records that. Neither is part of the gate. This is the whole procedure, for any agent to repeat (the owner, 2026-10-16: *"documentation of your demo creation process, so it can be easily repeated by any agent working on this package"*).

**When.** After a change to the portal's look, to a demo's team, recipes, models, scenarios or title, or when the owner asks. The docs guard pins each video to its page and the combined video to every part by its sha256, so any video recorded again means the combined video is made again.

**Before you start.**
- A built tree: `npm install && npm run build`.
- colima running, and every model the demos' recipes name in the shared model cache (`ASHA_MODELS_DIR`, by default `~/.simplyautonomous/harness/models`): `demos:record` refuses a demo whose model is missing, since a download would stretch its recording.
- The pinned headless Chromium, with Playwright's own ffmpeg: `npx playwright-core install --no-remove chromium-headless-shell firefox` ([the browser tests](#integration)).
- For the MP4 only: Homebrew's ffmpeg, which has libx264 (Playwright's encodes VP8 alone). Install it with `HOMEBREW_NO_AUTO_UPDATE=1 brew install --dry-run ffmpeg` first, to see that it upgrades nothing installed; record `llama-server --version`, `colima version`, `limactl --version` and `brew list --versions llama.cpp ggml colima lima openssl@3` before and after, as the 2026-10-16 install (`evals/probes/demo-mp4-2026-10-16/README.md`) did.
- The Mac awake, on power with its lid open, the commands run under `caffeinate -dims` ([the gate](#gate)), and nothing else running on the machine: no gate, agent suite or eval. Each recording and the combined video take the [agent-suite lock](#suite-lock), and a unit or integration run is refused while they hold it.

**1. Commit first.** `demos:record` refuses a tree with a change outside `docs/patterns/videos/` and the results paths; `demos:reel` refuses any change. A clean worktree of `main` works too, with its videos copied back to the main checkout afterwards:

```sh
git -C <checkout> worktree add --detach <dir> main   # node_modules copied; nothing needed beside it
cd <dir> && npm run build
```

**2. Record.** `npm run demos:record` records all 25 in catalogue order — about 30 minutes (32 on 2026-10-11) — or name some: `npm run demos:record p06 p20`.

- `demos:record` ([`record.mts`](../../tools/demos/record.mts)) refuses before recording anything when the tree has a change outside `docs/patterns/videos/` and the results paths, or when a model a named demo needs is not in the shared model cache, naming each. For each demo it runs the suite with `ASHA_RECORD_DIR` set to a folder of its own under `<tmp>/asha-record-*/`, encodes the frames under the agent-suite lock, and promotes the video to `docs/patterns/videos/<page>.webm` with its sidecar `<page>.json` only when nothing refuses it: every scenario passed, the video ran on at least 3 s after its chat's last line (the recorder holds up to 30 s for it; demo-scene-refresh R12), the frame held, every followed restart, no failure the page showed or reported outside a followed stop's own lines, the capture's speed and gaps, the tree and `HEAD` unchanged, at most 10,000,000 bytes, and no private text in any document's thread or in the title — the scan reads them as text; the scene draws only what the thread holds, its canvas is not read. A recording not promoted stays in its folder with `refused.json` naming why; the command then exits 1, naming each demo.

**3. After recording.**
- Restore the results files: `git checkout -- tests/agents/results/`. Each recording runs its suite, which writes its results file; the committed results stay the gate's.
- Update each recorded page's **Watch it run** line — the commit, the date, the models and the length — from its sidecar `docs/patterns/videos/<page>.json`.
- Run the docs guard and read its exit status, not a grep of its output: `npx vitest run tests/unit/docs.test.ts; echo $?`. Every check must pass but *the combined video and its sidecar … agree*, which keeps naming the old parts until step 4.
- Commit the videos, their sidecars and the pages.

**4. The combined video.** *Since 2026-10-17 it is not committed here: the website serves it, version-controlled in its own repository, and the catalogue plays that copy (`demo-reel-mp4`); `docs/patterns/videos/demos.webm` is git-ignored, and the MP4 below goes to the website's session.* `npm run demos:reel` ([`reel.mts`](../../tools/demos/reel.mts)) refuses until every video it plays is promoted (all but P25's, which it leaves out), while another process holds the agent-suite lock, and on any change outside the results paths. **Outputs.** `<out>/<model>.json` and a table on stdout. ## Which demos a change repeats {#selection}

`npm run demos:select` ([`evals/patterns/select.ts`](../../evals/patterns/select.ts), the library [`evals/patterns/selection.ts`](../../evals/patterns/selection.ts); since 2026-09-29, `docs/plans/demo-selector.md`) runs in the gate after a build and before the agent suite. It writes `tests/agents/results/selection.json`: per demo of the manifest, `repeats` (3 or 1) and a `reason`, with the commit it was computed at, the base, and the changed files.

- **The base** is the `commit` of the committed `tests/agents/results/gate.json`, read from `HEAD`, used only when it parses, names a 40-hex commit other than `HEAD`, says `dirty: false`, its `results` sha256s match those files at `HEAD`, its `environment` equals the current fingerprint (`environmentFingerprint`: `node`, `llama-server --version`'s version and `built with` lines (its log line carries a per-run elapsed time), `colima version`, `docker version` against colima's socket, the sha256 of `node_modules/.package-lock.json`, and each cached model the demos' recipes name), and `git merge-base --is-ancestor` exits 0. Otherwise every demo is selected three times with `no-base: <why>` (`no-record`, `unreadable`, `dirty`, `environment changed`, `not-ancestor`, `unknown-commit`) and `baseDetail` saying why.
- **The changed files** are the union of `git diff --no-renames` against the base and against `HEAD`, untracked files not ignored by the committed `.gitignore`, every untracked `.gitignore`, every untracked file under `teams/`, `docs/patterns/` and `tests/agents/` whether ignored or not, and every file `git ls-files -v` flags (skip-worktree, assume-unchanged); every git call overrides `core.fileMode`, `core.fsmonitor` and `diff.ignoreSubmodules`, so no local setting hides a change. A file under the demo's team folder, its page, render or diagrams, or its suite is **own** (that demo, three repeats); under `tests/agents/results/`, `evals/routing/results/` (`RESULTS_PATHS`, which [`support.ts`](../../tests/agents/support.ts)' dirty check imports) or `docs/` outside `docs/patterns/`, **no demo**; anything else is **shared** (every demo). A demo nothing touches is `untouched`, one repeat. `--full` selects every demo three times (`full`).
- **It fails the step**, writing nothing, when any git command fails or times out (30 s each), when the manifest is invalid, when git's work tree is not the repository (an inherited `GIT_DIR`), when a demo's team name is not a plain folder name, and when a demo's team folder, page or suite is reached through a symlink (at it or any folder above it) or its team folder holds one. A unit test also fails when a manifest entry names a team other than the one its page launches ([`pattern-coverage.test.ts`](../../tests/unit/pattern-coverage.test.ts)). The error is one JSON line on stderr, `event: "demos.select_failed"`.
- **A checkout whose `node_modules` is a symlink** (a worktree linked to another checkout's packages): `.gitignore`'s `node_modules/` matches only a directory, so git lists the link as untracked and it is shared — every demo is selected three times. That costs time, never a missed repeat; the gate's run folders hold a real `node_modules` (a copy), as AGENTS.md's layout does.
- **What it changes today: nothing but the record.** No `gate.json` is written yet (the gate record is <span class="badge planned">planned: enterprise-targets</span> with the three repeats), so every selection is `no-base: no-record`, and the gate runs each agent-suite file once whatever it says. Repeats 2 and 3 will read their suites with `suitesForRepeat`, which refuses a missing selection or one from another commit. The [report](agent-tests.html)'s pattern sections show a demo's line (`selected 3 repeats: …`) only when the selection is from the same commit as its results; otherwise `3 repeats: no selection`.
- **Proven to fail:** the unit tests ([`demo-selector.test.ts`](../../tests/unit/demo-selector.test.ts), over temporary git repositories) and 32 mutations of the selector, the entry, the report, the coverage test and the chain, each caught (`evals/probes/demo-selector-2026-09-29/mutations.mjs`, its log (`evals/probes/demo-selector-2026-09-29/mutations-d076699.log.txt`) at `d076699`).
