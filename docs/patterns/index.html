Pattern demos

How a demo runs

Every demo is a team folder, teams/<team>/: its team.json, each member's recipe, and each member's guidance, a numbered workflow in Markdown that is part of its system prompt (team). You run it with two commands — ./asha --launch team=<team>, then ./asha to=<handle> message="…" to one member (or without to=, to everyone) — exactly as its page's run-command block gives them; the page's commands are the ones its test runs. The block is marked asha-run: its first line is the team's launch, its second the pattern's bound on a request (# bound: <ms> ms), then each scenario's id (# pNN-x) and its command — or its commands, run in order, a later one naming conversation=@previous, which the suite fills with the conversation id of the scenario's command before it (an answer into the same conversation; docs/plans/patterns-phase-3.md R9). A scenario may also stop the daemon, ./asha --stop, and launch a team again, ./asha --launch team=<team> — exactly these forms — as P20's do (docs/plans/patterns-phase-5.md R8).

Its agent-suite file, tests/agents/pNN-<slug>.test.ts, runs exactly the commands on its page, and every assertion of its proof is one checker, unit-tested on fixtures that each break one claim (Testing).
