The tavily module

tavily gives an agent one tool, tavily__search: a web search through Tavily's Search API (a paid web-search service), at its basic search depth, returning each result's title, URL and an extract of its content. It is the reference ToolModule, and the example the walkthrough builds from.

verified 2026-10-02built 2026-10-02; never run against Tavily (no live call made)code: modules/tavily/index.mjs, module.jsontests: reference-module-calls.test.ts against a fake built from Tavily's docs (D49)

In short

  • One tool, search {query, max_results?}, classed untrusted-input and egress; 5 results unless the model asks for another number.
  • It reaches one host, api.tavily.com, with one secret, TAVILY_API_KEY, through the egress proxy.
  • Metered at 1 credit a search, $0.008 a credit; approved by the owner up to $25 a month; off until asha --enable-module.
  • Plain JavaScript with no dependency: Node's fetch only.

What it sends and returns

call('search', {query, max_results}, context) sends one POST https://api.tavily.com/search with Authorization: Bearer <key> and the body {query, search_depth: "basic", max_results, include_usage: true}, bounded at 25 s (inside the tool's 30 s). It returns {query, results: [{title, url, content}]} — never Tavily's raw_content (a whole page) — and Tavily's reported usage.credits as {units}, which settles the meter. A non-2xx answer is module_unavailable naming only the status; a body that is not JSON, module_unavailable; its own bound, timeout. Facts read 2026-10-01 from Tavily's search reference: the endpoint, the bearer header, search_depth (default basic), max_results (default 10), include_usage (default false; when true the answer carries usage with the request's credits).

What leaves the machine: the query the model writes, which may hold anything in the agent's context — the user's words, a file's text (the stated limit) — and the key. Tavily's answer is untrusted text: it reaches the model only inside a tool result, which the tool's description tells the model to treat as data.

Cost and approval

Approved: by the owner, 2026-09-27, cap $25 a month.

The estimate the owner approved (record live-vendor-cost-estimate, 2026-09-27, the plan's R18a (docs/plans/extension-modules.md)): 500 basic searches a month × 1 credit × $0.008 a credit, after the account's 1,000 free monthly credits ("You get 1,000 free API Credits every month", and a basic search "costs 1 API credit": API credits, read 2026-10-02) = at most $4.00 a month. The owner's $50 cap over both reference modules is split $25 here and $25 to bedrock.

The key is one the owner already holds, reused (the owner, records tavily-key-reuse and tavily-key-choice, 2026-09-27): no new key is made, and the owner enters it with asha --set-secret module=tavily name=TAVILY_API_KEY when live use starts. It is never committed, logged, or put in a recipe or an agent container. A file that holds it in plain text is refused to any command plugin by the content scan, should it lie inside an allowed root.

The vendor-side limit: none is set at Tavily (the owner's answer to record live-run-values, option (b), 2026-10-12, before live use started): asha's meter alone holds asha to its $25 a month on Tavily, and nothing caps the key's total spend, since the meter counts only asha's searches on it. (Until 2026-10-12 this said one Tavily-side monthly limit on the shared key, covering both projects, at an amount the owner would choose and set when live use started — the owner's answer O3, record tavily-limit-with-shared-key, 2026-09-28.)

ConcernWhat holds it
The key leaksIt is only in its module's container environment; every line the module prints is redacted; the fake and every fixture carry a placeholder, never a tvly- prefix (a test scans the module's files)
The module reaches elsewhereOnly api.tavily.com:443, by the egress proxy, its server name checked; its network is internal
